# BEN Route Performance Lab

一个仅在浏览器本地运行的司机—线路历史表现分析原型。它连接两份GOFO DMS导出文件，按司机、区域和ZIP汇总妥投表现、容量与异常情况。

## 隐私边界

- 本仓库和网页代码公开，但仓库不包含真实运营数据。
- Excel在浏览器本地读取，不上传到GitHub或本项目的服务器。
- 分析不使用收件人姓名、手机号、邮箱、客户单号或申报货值。
- ZIP地图只向邮编查询服务发送5位ZIP，不发送街道、运单号或司机信息。
- 请勿把真实Excel、CSV或其他运营数据提交到公开仓库。

## 使用方法

1. 打开GitHub Pages网页，或下载仓库后双击 `index.html`。
2. 上传配送监控表和运单明细表。
3. 点击“连接并分析”。
4. 点击“定位ZIP”生成近似区域地图。

首次打开需要联网加载Excel解析组件、Leaflet地图组件和OpenStreetMap底图。原始Excel仍只在本地浏览器中处理。

也可以点击“加载脱敏示例”查看界面和功能。

## 两份输入文件

### 配送监控表

核心字段：

- 运单号
- 邮编
- 中心签出日期
- 快递员取件时间
- 快递员名称
- 快递员操作状态
- 运单最新状态
- 签收时间
- 妥投时效
- 问题件类型
- 任务编码
- 快递员区域名称

### 运单明细表

核心字段：

- 运单号
- 收件城市
- 收件地邮编
- 预报重量或结算重量
- 预报体积重
- 运单状态
- 操作人
- 快递员工作区域名称
- 是否退件
- 最新操作时间

两张表使用标准化后的`运单号`连接。如果运单明细中存在重复运单，系统优先采用最新操作时间较新的记录；配送监控中的重复行会保留，以免误删二次配送尝试。

## 第一版分析方法

- 线路画像：`快递员区域名称 + 5位ZIP + 当日货量`
- 准时妥投：`签收时间 <= 妥投时效`
- 调整后准时率：司机样本与车队整体表现进行小样本收缩，先验强度为50票
- P75日容量：司机在该区域历史单日件量的75百分位
- 推荐排序：先判断容量是否适配，再按调整后准时率、熟悉天数和容量余量排序

第一版没有根据主观权重生成综合分数。推荐结果采用分层排序，便于解释和后续回测。

## 已知限制

- 地址门牌被隐藏，因此地图显示ZIP中心点，不能规划逐户导航顺序。
- `最新操作时间`仅在监控表缺少签收时间且运单状态显示签收时作为推测时间，并在内部标记为推测值。
- 数据中的“已退回站点”和“签收”可能同时出现，系统会把它标记为状态矛盾，需结合业务规则复核。
- 司机推荐仅反映上传数据覆盖的车队和日期范围。
